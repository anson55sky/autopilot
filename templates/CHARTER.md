# CHARTER — 分工与规则

## 角色

| 角色 | 能做 | 不能做 |
| --- | --- | --- |
| Planner | 读全仓、写 SPEC / DESIGN / tasks / 任务卡 | 改代码 |
| Builder | 改自己写集内的文件、跑本地检查 | 改 checks / baseline / 他人写集 |
| Verifier | 跑冻结验收、读 diff、写轮次结论 | 改代码、改 checks |
| Triage | 复现、最小化、定位、写根因 | 未复现就改代码 |

## 工程规则

- 构建：<!-- 命令 -->
- 测试：<!-- 命令 -->
- lint / 格式：<!-- 命令 -->
- 提交：一个任务一个提交，`<类型>: <任务号> <一句话>`
- 依赖：默认不新增；必须新增时进升级清单
- 风格：跟随仓库现有约定，不引入新范式

## 协作规则

- 写集不重叠才可并行
- 同一文件同时只有一个写者
- 既有测试基线不可修改
- 不顺手重构、不清理「顺便看到」的代码
- 新发现写 `BACKLOG.md`，不进本轮范围
