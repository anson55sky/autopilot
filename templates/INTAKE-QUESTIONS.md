# INTAKE 澄清问卷（E7 引导澄清）

用途：使用者在签目标契约前，控制器用**这一份**问卷把项目问清楚。一次交互批量完成，
不是多轮对话拉锯；运行期不再有提问机会（不可逆动作审批除外）。

## 硬规矩

1. 问题总数 **≤5**（GOAL 的 `FLEX_RULES` 可收紧，不可放宽）。
2. **影响性过滤**：只有"不同答案会导致交付物形态或验收阈值实质不同"的问题才有资格上卷。
   判据写不出来就不许问，改用默认值进假设。
3. 每问必须含四要素：**为什么问（影响什么）／候选项（≤4，含推荐）／不答的默认值／答案写进哪条验收**。
4. 使用者跳过的问题 = `defaulted`，默认值照常生效并留痕；不存在"问了你没答所以我不干了"。
5. 答案按 B8 带签发者写入 `GOAL.md` 的「澄清记录」小节；澄清记录是契约的一部分，改它 = 契约变更（走提案簿）。
6. 三类维度必须各至少尝试覆盖一次（覆盖不了就在卷尾声明"该维度按默认处理，理由是…"）。

## 问卷模板（控制器照此生成，方括号为占位）

```
目标：<使用者原话>

Q1 [交付物形态] 你要的最终产物是什么形态？
    为什么问：决定验收矩阵的判定通道（CLI 输出 / HTTP / 截图 / 产物文件 / App 包）。
    候选：<A｜B｜C｜D>，推荐 <X>，理由 <…>
    不答默认：<最无聊形态>，将写进 A#<…> 的判定方式。

Q2 [完成口径] "做完"以什么为准？请挑最接近的一条：
    为什么问：验收矩阵的阈值直接由它推导；写不出可判定的"完成"就不开工（铁律 1）。
    候选：<可执行判定 A｜可执行判定 B｜暂不可判定→建议先用探索先行模式>，推荐 <X>
    不答默认：<从目标反推的最严可判定口径>。

Q3 [环境与红线] 跑在哪、依赖什么、绝对不能碰什么？
    为什么问：决定 SKIP 语义的适用范围与不可逆清单的补充项。
    候选：<本机 / 指定环境 / 未知→按当前机器探测>，推荐 <X>
    不答默认：当前机器探测 + 基线不可逆清单。

Q4 [影响性提问，可选] <只有当两个答案会产生不同交付物时才问>
Q5 [影响性提问，可选] <同上>

卷尾声明：<哪些维度没有覆盖、按什么默认处理、为什么>
```

## 判定通道速查（帮使用者把 Q2 说成可判定的）

| 产物形态 | 可执行判定举例 |
| --- | --- |
| CLI / 脚本 | 退出码 + stdout 匹配 + 黄金样例 diff |
| Web / UI | 无头浏览器探针：DOM 结构、截图像素差、交互事件序列 |
| 库 / 服务 | 单元与集成测试 + 合同测试 + 基准阈值 |
| 文档 / 数据 | 结构校验（schema）+ 抽样人审项显式标为 SKIP |
| App | 构建 0 警告 + 启动探针 + 关键路径 UI 自动化 |

## 反模式（出现即废卷重来）

- 问了"你想要什么风格/颜色"这类不影响验收阈值的问题（好奇心，不是影响面）。
- 把问卷当成让使用者替控制器做方案设计（方案是 DESIGN.md 的事，且 ≤3 选项自己写）。
- 问题超过 5 条、或一问多题的复合问卷。
- 使用者答完之后在运行期又冒出新问题（该走假设或提案簿，不走提问）。
