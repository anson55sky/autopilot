## 验收矩阵 · preset=feature（一个能一次讲清的功能）

写法要求：矩阵按「先证明它是缺的 → 竖Slice → 全量 → 退化路径」四段排，
不要一上来就列十条并列的界面断言——那样第一条永远无法证明是这次做的。

判定输出口径与所有档一致：每条 A# 在 `.autopilot/checks/run.sh` 里打一行
`RESULT <A#> PASS|FAIL|SKIP <一句话证据>`，全绿退出 0；有 SKIP 时 REPORT 单列并附环境声明。

| 段 | # | 验收条目 | 判定方式 |
| --- | --- | --- | --- |
| 缺口 | A1 | 功能位当前不存在（可证伪的前提） | 针对该行为的探测脚本在实现前退非零；实现后同一脚本退 0 |
| 竖切片 | A2 | 核心链路端到端跑通一次 | 一条命令走完输入→处理→可见输出；断言最终状态，不只看"没报错" |
| 主路径 | A3–A5 | 每个主界面/接口的成功态 | 逐条一个判定：接口返回结构断言 / 界面渲染后的可访问性树或几何断言 / 落盘产物内容断言 |
| 状态完备 | A6 | 空态、加载态、错误态各自可见 | 人为造三种输入，断言三种输出互不相同且都有明确文案（不接受"白屏/无限转圈"当加载态） |
| 边界 | A7 | 边界输入不崩、不静默吞 | 空值、超长、非法类型各一条，断言错误信息里点到具体字段 |
| 回归 | A8 | 既有验收全绿、无新增失败 | `sh checks/run.sh all` 退 0，FAIL=0，SKIP 单列 |
| 退化 | A9 | 能力缺失时判 SKIP 而非 FAIL/假过 | 把某依赖关掉（如无浏览器/无网络），断言对应条目输出 `SKIP <原因>` |
| 成本 | A10 | 新增代码量与矩阵条数相称 | 报告改动行数；实现量超过任务卡描述量级两倍 → 先停下来问方案（反模式表） |

## 非目标

不做未列入矩阵的"顺手优化"；不在本 run 内放宽矩阵（要改走提案 + epoch，下个 run 生效）；
不引入新第三方依赖，除非 GOAL.md 的「交付物」里明写。

## 并行与弹性（本档常用）

- `CONCURRENT` 打开：并行 ≤2，写集必须逐文件不重叠；flex 卡一律串行（`FLEX-SERIAL`）。
- `FLEX_RULES` 留空即吃默认档（每轮 light ≤2、flex 占比 ≤20%、零进展连击 2 次禁 flex）。
  要改就写进 GOAL.md，不要口头改——run 内改口径等于移门柱。

## 常见盲区（REPORT 必须逐条回答）

- A6 的三种态是"截图看起来对"还是"断言了状态"？前者不算验收。
- 错误态有没有把原始异常直接暴露给用户（泄漏路径/凭据形态）？
- 视觉类断言只验了字节数？几何冲突（浮层压 HUD）需要 `probe-geometry.mjs` 这类判据（H33①）。
- 界面改动有没有在真实运行体里验（构建产物而非源码渲染）？
